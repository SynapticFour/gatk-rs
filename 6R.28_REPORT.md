## 1. VERDICT

**Yes.** The mid-B `call_region(None)` is explained by a Rust keep-mask that is **not** GATK 4.4 `AlleleFiltering.filterAlleles`.

**OBSERVED JAVA SOURCE:** default Illumina HC sets `filterAlleles=false`. `HaplotypeCallerEngine.callRegion` does not call `filterAlleles`. When the flag *is* on, haplotypes are removed only if they contribute a **weak competing allele** (inverse-PL / SOR). Sharing a well-supported SNP across haplotypes is not a drop reason. There is no `exact.len() == 1` unique-supporter rule.

**OBSERVED RUST (pre-fix):** contig-2 `strict_java_snp_rank_only` kept an emit-band SNP only if exactly one haplotype supported it. Two C/A ALTs → both discarded → REF-only → `has_variation_for_calling() == false` → `None`.

**IMPLEMENTED CONTRACT:** production keep-mask now retains every haplotype that supports any EventMap allele in the active span (Java default: filter not invoked). Unique-supporter is test-only legacy so the 4→1 collapse can still be reproduced. No contig/position/P12/mid-B special case.

### Algorithm when the flag is on (OBSERVED JAVA SOURCE)

`subsetHaplotypesByAlleles`:

1. Collect non-ref alleles from each haplotype EventMap (`getAlleles`).
2. Competing pairs = alleles that **do not co-occur** on the same haplotype, restricted to close (0–3 bp) or same-up-to-hmer (0–20). Connected components are scored together.
3. Per cluster: inverse-PL (`AlleleFilteringHC.getAlleleLikelihoodVsInverse` = `min(PL1-PL0, PL2-PL0)`) and SOR. `identifyBadAlleles` vs QUAL/SOR thresholds. Stringent pass uses QUAL 1.
4. If weak candidates exist (cluster size > 1, or lone stringent-weak, or `filterLoneAlleles`): disable **all haplotypes that contribute the first filtering candidate**.
5. Output = haplotypes not disabled. Reference is kept unless it contributed a filtered allele. Multiple ALT haplotypes can survive. Filtering is generic, not coordinate-specific.

**Weak competing allele:** allele in a competition cluster with inverse-PL worse than the QUAL threshold and/or SOR above threshold.

Filtering operates on **alleles clustered by competition**, then **haplotypes** that contribute a filtered allele, using **read×haplotype likelihoods**. Not on unique haplotype count.
