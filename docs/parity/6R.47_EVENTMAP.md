## Java source contract

`EventMap.processCigarForInitialEvents` (4.4.0.0 `EventMap.java`):

- `D`: REF = padding base + deleted bases, ALT = padding base; skip if `refPos == 0` or non-regular bases. **No length cap.**
- `I`: skip if first/last CIGAR element (unresolved) or `refPos == 0`. **No length cap.**
- `M`/`EQ`/`X`: regular-base mismatches, grouped by `maxMnpDistance`.
- `N`/`H`/`P`: throw.

The Rust-only `len <= 40` filter (comment: “mega-alleles from bad SW”; R4-2 raised 4→40) is **not** a GATK 4.4 EventMap rule. It remains a search bound for **read-event discovery** only.

## Rust pre-fix

`variation_events_for_haplotype` (and supplemental INDEL-SW EventMap) discarded events with `REF` or `ALT` length > 40. A `171D` (REF length 172) never entered `getVariationEvents`.

## Root cause

Without the 171D, trim saw SNP-only events → 77 bp window inside the D → Java-equivalent `Haplotype.trim` dropped `28M171D160M` → SNPs 635/653/670 vanished from the VCF.

## Production change
