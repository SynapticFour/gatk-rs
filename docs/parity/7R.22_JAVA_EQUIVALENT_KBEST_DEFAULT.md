## Production change

`SeqKbestResourcePolicy::from_runtime` still calls `parse_policy`. The unset branch now returns `UnboundedDiagnostic`.

| env `GATK_RS_EXPERIMENTAL_KBEST_POLICY` | policy |
| --- | --- |
| unset / empty / `0` / `off` | `unbounded_diagnostic` |

| `byte_budget` | unchanged; still requires `GATK_RS_EXPERIMENTAL_KBEST_MEMORY_BUDGET` |
| anything else | configuration error |

`UnboundedDiagnostic` still only disables the `BinaryHeap.len() >= 1024` refusal. K stays `num_best_haplotypes_per_graph` (128 on `CallRegionArgs::strict_java`). The per-vertex visit limit stays that same K. Score and heap order are unchanged. Path-edge cap 4096 and expansion cap 12000 stay in the search loop. `GatkError::memory` and `GATK_RS_HC_RSS_ABORT_MIB` are unchanged. No new frontier cap and no new byte budget. The variant was not renamed.

`legacy_1024` is no longer the default. It remains selectable.

Previous default, unset env: `legacy_1024`, refusal `heap_len<1024`.

## What was not changed

No edit to PairHMM, genotyping, annotations, or VCF algorithms. No Java oracle edit. No graph-specific or coordinate-specific branch. `SeqKbestCapPolicy::production()` still records the historical forensic caps, including heap 1024; production search does not consult that forensic struct.
