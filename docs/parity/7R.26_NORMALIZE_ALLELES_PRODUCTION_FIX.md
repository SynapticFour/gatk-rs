# 7R.26 — Production fix for normalize_alleles caller ownership

7R.26 CLASSIFICATION = `RUST_NORMALIZE_ALLELES_CALLER_OWNERSHIP_FIX_REPRODUCES_JAVA`

One production semantic change: `left_align_indels` now keeps the `IndexRange` values `normalize_alleles` already wrote. The normalization algorithm, `IndexRange`, Smith-Waterman, scoring, overlap filtering, and genotype-likelihood arithmetic were not changed.

## 7R.25 cause

`normalize_alleles` takes `bounds: &mut [IndexRange]` and mutates that slice through `iter_mut`. `IndexRange` is `Copy`. The call

```rust
normalize_alleles(..., &mut [ref_indel, read_indel], ...)
```

built a temporary array of copies. On the 7R.24 diagnostic block the function moved that temporary to reference `[99, 99)` and read `[5, 5)` and returned `start_shift = 111`, `end_shift = 112`. The temporary was dropped with the statement. Lines 803–846 then read the named variables, which were still `[210, 211)` and `[116, 117)`.
