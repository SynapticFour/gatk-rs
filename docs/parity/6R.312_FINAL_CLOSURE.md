## Objective

Make clipped PairHMM/genotyping reads use Java `ReadCoordinateComparator`, after the anchored tandem-repeat trim, the failed-mate evidence exclusion, and the Jacobian heterozygote combine were already production behavior.

## Old Rust behavior

The pre-6R.312 clipped-read sort was `(tid, pos, qname)`. At clipped start `29455560` that put reverse read `HISEQ1:11:H8GV6ADXX:1:1109:9994:7054` flags 83 before forward read `HISEQ1:11:H8GV6ADXX:1:1116:4033:65919` flags 99.

The 122×3 allele matrix already matched Java. Genotype likelihood index 3 differed by 2 ULP and index 5 by 1 ULP. Replaying the same matrix in Java order matched all six Java GL bits.

## Comparator

`java_read_coordinate_compare` in `assembly_region_finalize.rs` is Java `ReadCoordinateComparator`: reference, assigned start, forward before reverse, name, flags, mapping quality, mate reference, mate start, fragment length.

Production calls it from `clip_finalized_reads_in_place`. Failed-mate removal from 6R.311 runs after that sort and keeps the surviving order. PairHMM and genotype accumulation do not sort the reads again.

The pre-6R.312 sort remains available only when `set_forensic_6r308_java_read_coordinate_order(false)` is set. Production default is the Java comparator.
