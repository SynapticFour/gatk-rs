## 6. has_variation_for_calling COMPARISON

**Rust predicate** (`AssemblyResultSet::has_variation_for_calling`):

```
!variation_events.is_empty() || is_variation_present()
```

`is_variation_present()` = `variation_present && haplotypes.len() > 1`.

**Java predicate** (`AssemblyResultSet.isVariationPresent`):

```
variationPresent && haplotypes.size() > 1
```

These are **not** equivalent by name:

- Rust can proceed with a non-empty EventMap even if `variation_present` is false.
- Java requires the variation flag **and** more than one haplotype.

For **this** None both are false **after** the allele filter (0 events, 1 hap). Before the filter both are true (4 haps; Rust also has events). The None is not a predicate-mismatch on an otherwise identical assembly; the assembly is REF-only by the time the guard runs.

Java `AssemblyRegionTrimmer.Result.isVariationPresent()` is `variantSpan != null` (any overlapping variant). That matches Rust `trim_result.variation_present` here (`true`). That early exit is **not** taken.

## 9. FIRST CAUSAL DIVERGENCE

**6R.27 FINDING**

First divergence:

Rust `select_haplotype_keep_mask` / `mark_haplotypes_supporting_variation_events` on contig `2` with `strict_java_snp_rank_only`:

- Keep REF.
- For each emit-band SNP, keep an ALT only if `exact.len() == 1` (or a single supporter).
- `allow_score_fill` is **false** on contig `2`, so leftover ALTs are not ranked in.

Two trimmed ALTs both have `92317399 A` (and T/C, G/C). `exact.len()==2` → **keep none**. Third ALT lacks C/A and its extras are not emit candidates → not kept. Filter retains REF only; post-filter EventMap sync yields 0 events.

Java 4.4:

`AlleleFiltering.filterAlleles` / `subsetHaplotypesByAlleles` clusters **competing** alleles and drops haplotypes that contribute **weak** alleles (inverse-PL `getAlleleLikelihoodVsInverse`, SOR). Sharing a strong SNP across two haplotypes is not a reason to drop both.

Rust:

`filter_assembly_and_likelihoods` after PairHMM, `AlleleFilterOptions::from_strict_java(true, original_active_start, original_active_end)`. Empty-likelihood replay of the same keep-mask (no PairHMM) also yields **1 REF / 0 ALT** — the drop does not require weak PairHMM scores.

Evidence:

- `six_r27`: `SUPPORT 92317399 n_alt_exact=2`, `EMIT_CANDIDATE 92317399 C/A = true`
- `STAGE after_early_allele_filter n_haps=1 n_alt=0 n_events=0`
- `STAGE_AFTER_ALLELE_FILTER_EMPTY_LL n_alt=0`
- Java source `AlleleFiltering.java` SHA `2dbc0258` (fetched this pass)

Causal: **YES**

Smallest faithful correction: do **not** require a unique contig-2 supporter for emit-band SNPs. Prefer Java’s competing-allele inverse-PL filter, or keep all haplotypes that support an emit-band allele (and let Java-style ranking cap them). Covered by a focused regression: two C/A ALTs must not collapse `call_region` to None. **Not implemented in 6R.27.**

Related non-causal divergences (do not “fix” as the None workaround):

- Trim padding accumulation (`max_end += pad` vs Java `Math.max`).
- Post-`trim_to` EventMap spray (172 bp hap vs 430 bp `reference_bases` in `collect_variation_events`).
