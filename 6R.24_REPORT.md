# 6R.24 REPORT — Java VCF provenance of mid-B C/A

Pinned Java: GATK **4.4.0.0** (`broadinstitute/gatk:4.4.0.0` / SHA `2dbc025821bc5f686c423ff332a41e6cef892a77`).

## 1. VERDICT

The oracle sites

`2:92317399 C>A`, `2:92317407 T>C`, `2:92317412 G>C`

(`GT=1/1 AD=0,2 PL=90,6,0 GQ=6 QUAL=78.32`)

were produced by **Docker GATK 4.4 HaplotypeCaller on the same NA12878_20k BAM** (and the same `hs37d5.simple.fa`) that the Rust tests use. A live Docker rerun on **`-L 2:92317000-92319000`** reproduced the three records **byte-for-byte** in FORMAT/QUAL.

Java assembled this ActiveFull region with **exactly two reads** and **k=25**:

```
Assembling 2:92317262-92317491 with 2 reads (overlap 2:92317162-92317591)
Not using kmer size of 10 … reference contains non-unique kmers
Using kmer size of 25
EventMap{2:92317399 C/A, 2:92317407 T/C, 2:92317412 G/C}
```

Rust skips k=10 **and** k=25 because `reference_has_non_unique_kmers` is applied to the **±500 bp padded assembly REF (1430 bp)**, which is non-unique at k=25. Java `createGraph` tests uniqueness on **`refHaplotype.getBases()`**, here the **430 bp extended-region haplotype**, which **is unique at k=25**.

**6R.23 stands:** the k=85 ALT island is a natural unique-k-mer miss **on the graph Rust actually builds**. Java never needed k=85 here.

## 9. JAVA 4.4 SOURCE BASIS

```java
        new SequenceForKmers("ref", refHaplotype.getBases(), ...), kmerSize).isEmpty())
    return null;
```

Uniqueness is **`refHaplotype`**, not `fullReferenceWithPadding`.

**IMPLEMENTED CONTRACT:** both skip k=10 when *their* REF sequence is non-unique. They disagree on **which** REF sequence.

## 10. CAUSAL CLASSIFICATION

**C — Proven Rust implementation divergence**

Same BAM, same FASTA, same 2 reads, same active/extended coordinates. Java runs **k=25** and emits the oracle VCF. Rust never attempts k=25 because the unique-kmer gate uses the **1430 bp** padded REF.

Not **D**: oracle is not a different BAM/interval/sample.

Not **A**: skipping k=25 is not Java-equivalent on this input.

6R.23’s k=85 island analysis remains valid **as a description of Rust’s last-attempt graph**, not as Java’s path here.

## 11. WHAT IS CLOSED

- Oracle = Docker GATK 4.4 HC on this BAM.
- Live Java reproduces QUAL/AD/PL.
- Same 2-read ActiveFull region as Rust.
- Three SNPs from one Java k=25 haplotype.
- Pileup / extra reads / `-L` mismatch are not the explanation.
