Allocation audit (2026-07-24) — gatk-haplotypecaller/src + gatk-core/src
========================================================================

Inventory: scripts/dev/allocation_clone_inventory.txt
  ~486 `.clone()` sites (excl. `/tests/` paths)
  Categories (post-fix heuristic): mostly (a) documented / (b) deferred / (c) cleared

Category legend
  a) NEEDED — multi-owner / HashMap key / cheap Arc|Copy → `// CLONE: needed because …`
  b) AVOIDABLE — borrow / take / Arc share would suffice (deferred when API-wide)
  c) HOT PATH — per-read / per-haplotype / per-locus loops (fixed first)

Fixes this iteration (c then high-value b)
------------------------------------------
1. activity_scoring + hc_joint_is_active
   - No per-locus clone of nonempty sample pileups; borrow `&[&[PileupObservation]]`.
2. read_threading_graph::create_vertex / into_assembly_graph
   - Move kmers/maps; clone HashMap key only when unique.
3. assembly::remove_nodes + DFS haplotypes
   - Move surviving nodes; DFS uses push/pop on `&mut String` (clone only at leaf emit).
4. genotype_limits + allele_subsetting
   - Top-2 without sort-clone; no `Vec<Vec<f64>>` of singleton rows.
5. genotype_gvcfs
   - `mem::take` remapped PL/AD.
6. read_downsample
   - Own records via `Option` slots — no BAM `Record` clones on keep/reservoir paths.
7. parity_spine / motif_cluster_discovery / locus_iterator / ref_confidence
   - Borrow event lists; avoid HashSet lookup key allocs; entry API; move terminal pileups.
